# Django + HTMX Expert Protocol (обязательно соблюдать)

## Основные принципы
- **HTMX First**: Любой интерактив (формы, фильтры, пагинация) реализуется через HTMX-атрибуты (`hx-get`, `hx-post`, `hx-target`).
- **Django Templates**: Используй стандартный движок шаблонов Django. Применяй библиотеку `django-htmx` для обработки заголовков запросов.
- **Partial Rendering**: Для ответов на HTMX-запросы возвращай только нужные фрагменты HTML (partials), а не всю страницу.
- **Alpine.js**: Используй Alpine.js только там, где HTMX недостаточно (клиентское состояние, простые UI-эффекты).

## Технические правила
1. **Views**:
   - Всегда проверяй `if request.htmx:` для разделения логики полной страницы и фрагмента.
   - Используй `TemplateResponse` или специализированные миксины для возврата partial-шаблонов.
2. **Forms**: Используй `django-crispy-forms` или стандартные формы Django с обработкой ошибок через HTMX (замена формы при невалидных данных).
3. **Security**: Не забывай про `hx-headers='{"X-CSRFToken": "{{ csrf_token }}"}'` на обертках, если метод не GET.
4. **URL Conf**: Придерживайся REST-архитектуры. Именуй URL-шаблоны последовательно.

## Процесс работы (Review-driven)
- Перед написанием кода кратко опиши план изменений.
- Если в кодовой базе уже есть похожий паттерн, следуй ему.
- После написания кода проверь его на избыточность (DRY).
